# Разработка Graal Hunt

Для инструментов разработки и CI используется **Node.js 24** (`.nvmrc`). На исходном `main` заявлен runtime Node.js ≥18 и только `ws@^8.18.0`; это требование, команда `npm start` и конфигурация Railway сохранены. Node 18 не подходит для новых dev-инструментов.

Совместимость проверена через npm metadata перед настройкой:

| Инструмент | Версия  | Требование Node.js                    |
| ---------- | ------- | ------------------------------------- |
| Vitest     | 5.0.5   | `^22.12.0 \|\| ^24.0.0 \|\| >=26.0.0` |
| Playwright | 1.64.1  | `>=20`                                |
| ESLint     | 10.13.0 | `^20.19.0 \|\| ^22.13.0 \|\| >=24`    |
| Prettier   | 3.9.10  | `>=14`                                |

Точные dev-версии и дерево зависимостей закреплены в `package-lock.json`. Production-зависимость `ws` не изменена в `package.json`; первый lock-файл фиксирует её разрешённую версию. Runtime на Node 18 отдельно не проверялся.

## Установка и проверки

```bash
nvm use
npm ci
npx playwright install --with-deps chromium
npm run check
npm run test:e2e
```

На Windows без nvm установить Node.js 24 вручную. `--with-deps` устанавливает системные зависимости браузера на поддерживаемых Linux-системах.

| Команда                | Назначение                                        |
| ---------------------- | ------------------------------------------------- |
| `npm start`            | Обычный сервер, порт `PORT` или 8765              |
| `npm test`             | Unit-тесты движка без сетевого сервера            |
| `npm run test:watch`   | Vitest в режиме наблюдения                        |
| `npm run test:e2e`     | Локальный Chromium и реальный HTTP/WS-сервер      |
| `npm run test:e2e:ui`  | Интерактивный запуск Playwright                   |
| `npm run lint`         | ESLint приложения, тестов и конфигурации          |
| `npm run format:check` | Проверка форматирования инфраструктуры и тестов   |
| `npm run format`       | Форматирование тех же файлов                      |
| `npm run check`        | Lint, Prettier и Vitest; e2e запускается отдельно |

## Границы настройки

`server.js` экспортирует движок через CommonJS. `require.main === module` оставляет запуск HTTP/WS-сервера команде `npm start`, поэтому импорт в unit-тестах не создаёт сокеты и таймеры. Правила не извлекались в новые модули и не переписывались.

Unit-тесты проверяют геометрию, детерминированную карту для 2–4 команд, выбор классов, очередность и таймер ходов, движение отряда и экипировку, предметы, Грааль, сериализацию, подготовку боя, инициативу и уровни. Это исходный регрессионный набор, а не полное покрытие всех боевых эффектов и действий ботов.

**Обычный локальный запуск клиента всё ещё использует фиксированный Railway WebSocket URL.** В Playwright WebSocket заменяется до выполнения клиентского кода и направляется на `ws://127.0.0.1:8877`; внешние HTTP-запросы блокируются. Изменять адрес Railway для тестирования не нужно. Сервер на 8877 запускается и останавливается Playwright; занятый порт завершит проверку ошибкой, чужой сервер не переиспользуется.

E2E-сценарии: health/title без ошибок JS и console.error, повторный выбор классов и вход в бой, создание комнаты и последовательный выбор классов двумя клиентами до карты. При ошибках сохраняются trace, screenshot и HTML-отчёт в игнорируемые `test-results/` и `playwright-report/`.

ESLint фиксирует исходный технический долг: 11 предупреждений `no-unused-vars` и одно `no-case-declarations` в приложении. Лимит 12 предотвращает рост общего числа предупреждений; новые файлы используют правила recommended без ослаблений. Старые файлы приложения и README исключены только из Prettier для предотвращения массового форматирования. При исправлении старых предупреждений следует уменьшать лимит.

Три скилла в `.agents/skills/` содержат инструкции по правилам, локальной диагностике WebSocket и безопасным изменениям. `AGENTS.md` задаёт общие правила проекта.

Workflow `.github/workflows/checks.yml` выполняет quality и browser при PR в `main`, а также поддерживает ручной запуск. Используются Node.js 24, `npm ci`, локальные тесты и read-only разрешения. При падении browser загружается диагностический артефакт. Workflow не содержит деплоя или слияния PR. Обязательность проверок для слияния определяется настройками GitHub и этим PR не изменяется.

## Прокрутка экрана выбора классов

Первый прогон обнаружил обрезанную кнопку «Назад» при 1280×720. После разрешения пользователя исправление ограничено `#screen-classpick`: вертикальная прокрутка, безопасное центрирование и запрет сжатия дочерних блоков. При достаточной высоте содержимое остаётся по центру; при нехватке высоты оно доступно через прокрутку.

Сценарий повторного выбора классов и входа в бой проверяется обычными кликами при 1280×720, 390×844 и 1440×1080. Исходный проблемный размер сохранён. Всего зарегистрировано пять браузерных сценариев. История и результаты приведены в `work-setup-results.md`.
