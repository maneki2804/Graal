[Прогон PR checks](https://github.com/maneki2804/Graal/actions/runs/40376579978) проверял коммит `b0ca45f85f247228f4b44a59cecafd143a2d0793` до разрешённого пользователем исправления интерфейса. Результаты ниже описывают первоначальное состояние.

- `public/` полностью совпадает с исходным `main`; это обнаруженный дефект существующего интерфейса. В рамках запрета на изменения UI он оставлен без исправления. Размер viewport, обычный click и проверка сохранены; force-click, skip и увеличение таймаута не применялись.
- Диагностика сохранена в [артефакте Playwright](https://github.com/maneki2804/Graal/actions/runs/40376579978/artifacts/12674103625) с retention 7 дней.

На этом этапе PR был оставлен черновиком до разрешённого исправления интерфейса и повторного прогона.

Набор тестов начальный: он не покрывает все эффекты боя, поведение ботов, таймеры очистки комнат и восстановление соединений.

В приложении остались исходные предупреждения ESLint и фиксированный Railway WS URL. Последний обходит только тестовая среда; обычный локальный клиент продолжает использовать production URL. README содержит исторические сведения о правилах и адресах; источником истины служит код. Эти вопросы не исправлялись, поскольку задача исключает изменение механики, интерфейса и продакшен-деплоя.

Изменение `server.js` ограничено экспортом движка и условием запуска сетевой части. При первоначальной подготовке `public/`, `railway.toml`, команда `start`, runtime `engines` и объявление зависимости `ws` были сохранены. В `main` напрямую ничего не записывается. Проект подготовлен для дальнейшей разработки в отдельной ветке на Node.js 24. Браузерные проверки работают в GitHub; текущий результат исправления приведён ниже. Локальная установка Chromium дополнительно ограничена доступом к CDN.

## Исправление по разрешению пользователя

Пользователь разрешил исправить обрезанную кнопку после подготовки среды. Правка затрагивает только CSS экрана `#screen-classpick`: добавлены вертикальная прокрутка, `justify-content: safe center` с fallback `flex-start`, внутренний отступ и `flex-shrink: 0` для дочерних блоков. Механика, WebSocket URL, сервер и Railway не менялись.

Регрессия 1280×720 сохранена и дополнена размерами 390×844 и 1440×1080. Во всех случаях используются обычные клики, включая «Назад» и «В бой!». Теперь Playwright регистрирует пять тестов. Локально `npm run check` снова прошёл: 20 unit-тестов, ESLint без ошибок с 12 прежними предупреждениями, Prettier. `git diff --check` прошёл. Полный браузерный прогон исправления запускается в GitHub; его итог записывается в PR.

Также проверены четыре установленных CLI напрямую из `node_modules/.bin`: Playwright 1.64.1, Vitest 5.0.5, ESLint 10.13.0 и Prettier 3.9.10. Все запускаются, повторная установка не нужна. ## Дополнительная ошибка отображения боя

[Прогон исправления прокрутки](https://github.com/maneki2804/Graal/actions/runs/40378241333) подтвердил, что «Назад» и повторный выбор классов работают на всех трёх размерах. Затем сценарий обнаружил `RangeError: Maximum call stack size exceeded` при входе в бой. Причина: взаимный вызов `renderCombatScreen` → `updateCombatUI` → `renderCombatScreen` в существующем клиенте.

Удалён обратный вызов от обновления кнопок к полной отрисовке. Все обработчики, вызывающие `updateCombatUI`, уже выполняют отрисовку боя; изменения механики и сервера не понадобились. Браузерная регрессия дополнительно проверяет по четыре карточки на каждой стороне и доступность кнопки атаки, а также отсутствие ошибок консоли. Итог повторного CI записывается в PR.
