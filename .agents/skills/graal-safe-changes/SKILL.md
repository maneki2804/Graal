# Graal Safe Changes

1. Прочитать `AGENTS.md`; проверить `git status`, текущую ветку и diff. Получить актуальный `main`, создать отдельную ветку, не затирать существующую ветку или чужую работу.
2. Определить минимальный список файлов и критерии результата. Сохранить механику, интерфейс, WS-протокол и Railway, если задача не разрешает их изменение.
3. Перед добавлением инструментов проверить их `engines` и peer-зависимости. Использовать Node.js 24 из `.nvmrc`, точные dev-версии и коммитить lock-файл. Не менять runtime-зависимости без необходимости.
4. Использовать существующие методы движка через экспорт `server.js`; не выделять большой новый слой ради тестирования. Не форматировать старые файлы целиком.
5. Запустить `npm run check`, `npm run test:e2e` по области изменений и `git diff --check`. Отличать предупреждения старого кода от новых ошибок; не использовать skip/исключения для сокрытия провалов.
6. Проверить итоговый diff относительно `main`, особенно `server.js`, `public/`, `railway.toml`, `npm start`, `engines` и runtime dependencies. Сохранить результаты проверок и ограничения в документации/PR.
7. Закоммитить только связанные файлы и отправить рабочую ветку. Создать PR в `main` с описанием результата и проверок, не сливать автоматически.
