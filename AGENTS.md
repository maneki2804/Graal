# Graal Hunt: правила разработки

- Работать в отдельной ветке от актуального `main`. Не коммитить и не пушить в `main`, не выполнять force-push и автоматическое слияние PR.
- Перед изменениями прочитать `package.json`, текущий diff и соответствующие участки кода. Сохранять чужие изменения.
- Делать небольшие изменения по задаче. Не выполнять массовое форматирование, обновление зависимостей или рефакторинг ради тестов.
- Не менять механику, баланс, интерфейс, протокол WS и продакшен-деплой без явной задачи пользователя. Не менять `railway.toml`, `npm start`, `PORT` и адрес Railway в рамках подготовки среды.
- Считать `server.js` источником истины о правилах; README может отставать от кода. `public/game.js` содержит клиентские зеркала констант, а не независимый движок.
- Использовать Node.js 24 (`nvm use`) для разработки и CI, `npm ci` для установки. Сохранять `package-lock.json`; runtime-требование сервера `>=18` не означает совместимость dev-инструментов с Node 18.
- Импорт `server.js` не должен открывать порты или запускать таймеры. Сетевой сервер запускается через `npm start`.
- Запускать тесты только локально. Playwright использует порт 8877 и заменяет WebSocket только внутри тестового браузера. Не проверять игру запросами к Railway.
- Для игровой логики запускать `npm test`, для клиента/сети — также `npm run test:e2e`. Перед PR запускать `npm run check` и `git diff --check`.
- ESLint проверяет приложение и новые файлы; существующие неиспользуемые переменные и объявление в `case` остаются предупреждениями (лимит 12). Не добавлять новые предупреждения и не отключать правила ради зелёной проверки.
- Prettier применяется к инфраструктуре и тестам. Старые `server.js`, `public/`, README исключены, чтобы не создавать массовый diff.
- В PR описывать поведение, проверки, ограничения и известные проблемы. Не утверждать, что проверки прошли, если они не запускались.

Проектные скиллы находятся в `.agents/skills/`:

- `graal-game-rules`: анализ и регрессионные тесты правил.
- `graal-websocket-debug`: воспроизведение проблем соединения локально.
- `graal-safe-changes`: минимальные изменения и проверка diff.
